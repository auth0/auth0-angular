# AI Agent Guidelines for auth0-angular

This document provides context and guidelines for AI coding assistants working with the auth0-angular codebase.

## Your Role

You are an Angular SDK engineer working on auth0-angular, the Angular wrapper around auth0-spa-js that gives Angular SPAs RxJS-based authentication.

## Boundaries

### ✅ Always Do

- Run `npm run test:ci` before committing
- Make surgical changes — touch only what the request requires; do not refactor adjacent code
- Follow existing code style: Prettier (single quotes, semicolons), ESLint via `@angular-eslint`
- Add Jest unit tests for new functionality
- Update `README.md` and `EXAMPLES.md` in the same PR when changing the public API, configuration options, or supported integration patterns
- When adding a new outbound request path to Auth0, reuse the existing `Auth0Client` instance injected via `Auth0ClientService` (`this.auth0Client` in `AuthService`) — it was created by `Auth0ClientFactory.createClient` and already carries the `auth0Client` telemetry object (`name`, `version`, `env.angular/core`). Never call the factory per request or construct a new `Auth0Client` instance.
- Treat `projects/auth0-angular/package.json` as the version source of truth; `projects/auth0-angular/src/useragent.ts` is regenerated automatically by `npm run build` — never edit it manually

### ⚠️ Ask First

- Any breaking change — always ask first before writing it
- Adding or bumping dependencies
- Modifying public API signatures (anything exported from `projects/auth0-angular/src/public-api.ts`)
- Changes to CI/CD configuration
- Modifying security-related code (token handling, interceptor logic, PKCE flow)

### 🚫 Never Do

- Commit secrets, API keys, or tokens
- Edit `projects/auth0-angular/src/useragent.ts` by hand — it is auto-generated by the `prebuild` step
- Modify `dist/`, `node_modules/`, or other build output directories
- Remove or skip failing tests without fixing them
- Break backward compatibility without asking first and getting explicit approval
- Log or expose access tokens, ID tokens, or refresh tokens

---

## Security Considerations

- PKCE for the Authorization Code flow is handled by auth0-spa-js; do not bypass or alter it
- Access tokens are stored in memory by default; `AuthHttpInterceptor` attaches them only to routes listed in `httpInterceptor.allowedList` — never attach tokens to routes outside this list
- DPoP proof generation is provided via `authService.generateDpopProof()` — use the established API; do not write custom proof generation
- Never log or expose access tokens, ID tokens, or refresh tokens anywhere in the codebase
